# Ref Validation Integration into Tarball Processing (cg-216d6)

## Summary

Integrated the `ValidateRefFiles` function into the tarball processing pipeline by adding a validation call in the `Materialize` function after pack files are written to disk.

## Changes Made

### Modified: pkg/warmstart/extract.go

Added validation in `Materialize` function (lines 307-324):
- Collects pack file names after writing to disk
- Calls `ValidateRefFiles` to check .ref file existence on filesystem
- Returns error if any .ref files are missing after materialization

## Integration Architecture

The ref validation now happens at two points in the pipeline:

1. **ParseTarball (existing)**: Validates .ref files exist in tarball data structure
   - Uses `CollectMissingRefFiles` (memory-based validation)
   - Catches corrupted input early
   - Prevents processing invalid tarballs

2. **Materialize (new integration)**: Validates .ref files exist on filesystem
   - Uses `ValidateRefFiles` (filesystem-based validation)
   - Catches filesystem write failures
   - Ensures complete materialization

This defense-in-depth approach ensures:
- Early detection of corrupted input (ParseTarball)
- Late detection of filesystem issues (Materialize)
