## Acceptance Criteria - ALL MET

✅ **AC1**: Tool enumerates and reports every distinct `key_id` found across all manifests
- Implementation: `EpochPreflightChecker.discover_all_keys()` in `migration/preflight_check_epochs.py`
- Walks entire `provider/year/month` corpus structure
- Aggregates partitions by `key_id` with detailed reporting

✅ **AC2**: Tool attempts a decrypt probe per epoch and reports pass/fail per `key_id`
- Implementation: `EpochPreflightChecker.validate_decryption()` with `ValidationResult` per key
- Tests actual Parquet file decryption (not just metadata validation)
- Returns detailed pass/fail results with error messages

✅ **AC3**: Migration refuses to start if any enumerated epoch fails to decrypt
- Implementation: `migrate_corpus.py:run_migration()` calls `validate_encryption_credentials()`
- Raises `ValueError` if any epoch fails, aborting migration before data processing
- Explicit error messages for failed epochs

✅ **AC4**: Test fixture includes at least one manifest referencing a retired (non-current) epoch
- Implementation: `migration/fixtures/create_epoch_fixture.py`
- Creates 3 epochs: 1 current (`epoch-2024-08-current`), 2 retired (`epoch-2023-12-retired`, `epoch-2022-06-ancient`)
- Proves retired epochs are NOT silently skipped

## Usage

```bash
# Run preflight check before migration
python migration/preflight_check_epochs.py <corpus_root> <credential_path>

# If preflight passes, proceed with migration
python migration/migrate_corpus.py <corpus_root> <postgres_conn> <credential_path>
```

## Design Highlights

1. **Actual decryption tests** - Reads sample Parquet files, proving end-to-end decryption works
2. **Abort loudly** - Exit code 1 on any failure, never silently skip inaccessible data
3. **Aggregate by key_id** - Efficient testing (one per unique epoch, not one per partition)
4. **Progressive reporting** - Real-time status updates during validation
