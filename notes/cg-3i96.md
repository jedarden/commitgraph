## Conflict Resolution

The script implements the plan's conflict resolution rule via `pkg/identity/ingest.go`:

```sql
ON CONFLICT (email) DO UPDATE
  SET login = excluded.login,
      source = excluded.source,
      resolved_at = excluded.resolved_at
  WHERE excluded.source = 'manual'
     OR (email_resolution.source <> 'manual'
         AND excluded.resolved_at > email_resolution.resolved_at)
```

**Rules**:
- Manual source always wins
- Otherwise, newer `resolved_at` wins
- Seed data respects these rules (older seed loses to newer live/manual)

## Implementation Details

**Data flow**:
1. Open SQLite database (`~/backups/claude-leaderboard/hot.db`)
2. Query all rows from `author_login_cache` table
3. Validate each row (non-empty email, login, resolved_at)
4. Skip rows with empty `github_login` (no negative-cache seeding)
5. Parse `resolved_at` timestamp from RFC3339Nano format
6. Set `source='seed'` on all rows
7. Ingest in batches (default 1000 rows) via identity endpoint
8. Apply conflict resolution rule (manual wins, newer wins)
9. Log comprehensive summary
