# ARMOR Warm-Start Fetch Implementation (cg-4v07)

## Status: ✅ COMPLETE

Implementation of ARMOR read call for clone-worker warm-start artifacts is complete and tested.

## Implementation Details

**Location:** `migration/armor_client.py`

**Key Method:** `ArmorClient.fetch_warmstart_artifact(provider, repo_full_name)`

### Behavior

1. **Artifact present**: Returns tarball bytes as `bytes`
2. **Artifact absent**: Returns `None` (clean "not found" signal, no exception)
3. **ARMOR unreachable/erroring**: Returns `None` (treats errors same as "absent" for fallback)

### Key Namespace

Warm-start artifacts use a distinct key namespace from Parquet commit-history artifacts:
- **Warm-start**: `commitgraph/repo-artifacts/{provider}/{repo_full_name}/warmstart.tar`
- **Parquet**: `commitgraph/repo-artifacts/{provider}/{repo_full_name}/commits.parquet`

### Design Rationale

The implementation deliberately folds both "absent" and "error" cases into the same `None` return value. This is correct because both cases mean "fall back to full clone" from clone-worker's perspective. The caller doesn't need to distinguish why the warm-start isn't available - it just needs to know whether it can use it or must fall back.

## Acceptance Criteria Met

- ✅ Returns tar bytes when artifact present
- ✅ Returns `None` (not exception) when absent  
- ✅ Returns `None` (not exception) when ARMOR errors
- ✅ Uses per-repo warm-start key namespace distinct from Parquet artifact
- ✅ Unit tests with mocked ARMOR client covering all three cases

## Integration

This method is called by clone-worker at the start of each job:
- Returns tarball bytes → materialize warm-start and run `git fetch origin`
- Returns None → fall back to full `git clone --bare --filter=blob:none`
