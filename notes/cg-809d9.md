## Implementation Architecture

### Phase 1: Enumeration (`discover_all_keys`)
1. Walks `provider/year/month` directory structure
2. Reads `_manifest` files from each partition
3. Extracts `key_id` and `epoch` from `encryption_keys` array
4. Aggregates partitions by `key_id` (deduplication)
5. Returns `Dict[str, EncryptionKey]` mapping key_id to metadata

### Phase 2: Probing (`validate_decryption`)
1. Iterates over each unique `key_id` from Phase 1
2. For each key_id:
   - Finds a partition with that key_id
   - Locates a sample Parquet file
   - Attempts to read the file (tests actual decryption)
   - Records success/failure with `ValidationResult`
3. Returns `List[ValidationResult]` with one result per key_id

### Integration
The `run_preflight()` method chains both phases:
- Phase 1 output (keys_by_id) → Phase 2 input
- Phase 2 output (validation_results) → final report
- Overall success = AND of all individual results

## Design Highlights

1. **Two-phase architecture** - Clear separation between enumeration (Phase 1) and probing (Phase 2)
2. **Efficient aggregation** - Tests one per unique key_id, not one per partition
3. **Actual decryption tests** - Reads Parquet files to prove end-to-end decryption works
4. **Abort loudly** - Exit code 1 on any failure, never silently skip inaccessible data
5. **Progressive reporting** - Real-time status updates during both phases
6. **Structured output** - CLI for humans, dataclasses for automation
