## Current Error Propagation Patterns

### Service Layer Patterns
1. **Return value propagation**: All service functions return (result, error) tuples
2. **Error wrapping via fmt.Errorf**: Common pattern for wrapping errors
3. **Structured error wrapping**: WrapError function for structured errors
4. **Context-based tracing**: Errors include context (CommitSHA, Email, TraceID, RecordKey)

### CLI Layer Patterns
1. **Modern CLIHandler**: Used in get-audit-logs
   - HandleError method exits with appropriate code
   - Structured error printing with verbose mode
   - Automatic error classification and hints

2. **Legacy log.Fatal**: Still used in many older commands
   - log.Fatalf with no structured classification
   - Direct os.Exit calls with hardcoded exit codes
   - Missing error context and classification

## Key Findings

1. **Two parallel error systems** exist (structured + warmstart-specific)
2. **Inconsistent CLI error handling** - mix of modern CLIHandler and legacy log.Fatal
3. **Comprehensive error metadata** in structured system (context, retry, recovery)
4. **Well-defined exit codes** with automatic categorization
5. **Traditional error wrapping still dominant** in service layer
6. **No error loss patterns detected** - consistent error checking
7. **Context tracking** for distributed tracing (TraceID, RequestID)
8. **Retry policies** embedded in errors (exponential backoff configuration)
